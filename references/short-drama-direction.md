# 1–5 分钟短剧：从故事交接到生成与剪辑

用于完整短剧、跨场叙事或需多个生成片段组成的影片。时长是导航，不是硬边界；十几秒也可以有小故事，一分钟也可能只有一场。按当前材料从所需阶段进入，不把完整流程变成每次都要填的问卷。

## 决定当前阶段

1. 只有零散 idea：由 idea-parser 整理目标、已有因果与未定故事决定；调用独立的 [JIN Story Development](https://github.com/weoiquan-art/JIN-Story-Development/blob/main/SKILL.md) 发展剧情。优先通过已连接 GitHub 的文件读取工具（必要时先发现工具），以 repository_full_name=weoiquan-art/JIN-Story-Development、path=SKILL.md 取得入口，再读其当前所需参考。公开网页不可访问不等于授权连接器也无法读取；不凭一个 Skill 名称声称已完成调用。
2. 已有获批剧情：直接提取最小 Story Package，不要求用户把已确定的故事再填一遍表或重新批准。只有真实缺失且会改变故事的项才返回故事讨论。
3. 已有分镜或部分成片：继承被接受的内容，仅处理尚未完成或用户要修改的部分。
4. 用户只要学习、比较或构思：交付到对应阶段。用户要完整提示词且故事与资产条件成立：继续完成下游，不在模块边界另问一次是否继续。

故事交接至少保留：当前故事单位、人物行动的原因与目标、关键阻碍／选择／后果（若该故事存在）、事件先后、必要对白、入口与出口、不能改变的事实、目标时长及仍未决项。故事短或目的简单时可简写；不为填字段发明冲突、反转或前史。

批准状态来自用户实际决定；自由探索是草案，不自动成为正式剧情或 Canon。只缺拍摄方法不退回故事层。外部故事 Skill 暂不可读时，说明缺少哪项方法资料，完成已能核对的 brief；已有完整获批剧情仍可进入视频执行，不因工具名未安装而重新编故事。

## 整片导演方案

先记录整片要让观众理解和感受的变化，再选择具体呈现方案。提供结论与简短理由，不输出冗长内部推演。

### 开头与信息顺序

- 第一眼看见什么具体画面，为什么从这里进入；可以是人物、空间、细节、行动或已批准的异常。
- 开头需要让观众知道哪些行动条件，留下哪个与故事有关的问题；不要求固定秒数钩子，不自动安排空镜或爆炸。
- 哪些已批准信息现在给出、哪些延迟到后面，以及延迟怎样影响理解。
- 结尾如何回应前面的事件，并把改变后的状态交给下一段。

改变呈现顺序若会改变悬念身份、核心因果或用户指定的事件顺序，先提出建议，不静默重排。

### 分场与节奏

给出当前片子的具体场次和推荐安排；不用“按需切换”代替实际方案。每场至少说明作用、可见事件、观众新获得什么、入口／出口及策划时长。

| 场号 | 时间／地点 | 本场作用与已批准事件 | 观众信息／感受变化 | 入口 → 出口 | 策划时长 |
|---|---|---|---|---|---|
| S01 |  |  |  |  |  |

说明相邻场为什么接在一起：前一场改变了哪项行动条件、留下什么问题或情绪，后一场怎样接收。核对各场预估之和与目标总长；内容不足时报告容量问题，不用重复空镜或新增剧情填满分钟数。

“平和—起伏—平和”可作为当前片子的节奏选择，不能成为固定三段公式。前后的平和可具有不同关系、认知与代价。紧张度、动作速度、声音密度与情绪强度分别判断；安静也可能紧张，升格也可能处于高潮。

动作、对白、发现、关系变化按当前段落任务轮流承担重点，可在同一镜重叠。打斗必须继承已批准的目的和后果；不用固定动作比例，不在所有平静段塞入蓄力，不为所有打斗添加强制休息。

## 场戏与镜头

每场由 scene-sequence-director 明确镜头数及各镜任务，shot-designer 再确定拍法。导演方案应简述关键决定：

- 为什么保留这一镜；删掉它会失去什么信息或感受；
- 为什么在这里切，或为什么保持连续观察；
- 当前景别与构图能看到哪项必要证据；
- 景别变化由切镜、人物移动、镜头移动或明确焦段变化中的什么造成。

一镜到底仍有内部阶段、注意力交接与走位，不等于没有分镜设计。一次生成可以包含多个镜头；一个计划长镜若分段生产，须标明接续方式，不能把计划中的无缝衔接说成已验证。

文字分镜用于组织信息、节奏和执行。图片故事板／关键帧用于解决具体构图或空间风险；不因做短剧而强制每镜生图。镜头总数、剪切次数与镜内景别变化分开记录，不能把每个时间段都计成一次切镜，也不预设景别配额。

## 生成单元与资产

使用能相互对应的编号：场 S01、镜 S01-01、生成单元 G01。数量按故事需要决定，不从编号推出固定数量。

| 生成单元 | 包含镜头 | 成片位置／预计可用长度 | 生成目标时长 | 实际资产／当前状态 | 进入／交出状态 | 拆分理由 |
|---|---|---|---|---|---|---|
| G01 |  |  |  |  |  |  |

- 区分整片剪辑时间与单次生成的局部时间。整片第 02:10 开始的单元，局部区间从 0 开始；不把整片分钟数塞进一次生成。
- 生成时长与最终使用长度可能不同；需要剪辑余量时说明用途，不能重复计入成片总长。具体入口的能力和参数未核对时只写制作假设，不发明可用时长或槽位。
- 资产职责来自已设计的镜头。先列全片复用清单，再为每个单元选实际要上传的子集；不把所有角色、场景和所有参考灌进每个 Prompt。
- 普通场景和普通动作可按既有资产规则使用文字生成。独特或承载关键结构的场景仍先完成 Scene Plate 检查。
- 资产未就绪时仍可完成导演方案和标注占位符的规划草案；依赖这些资产的最终可提交 Prompt 等实际验收后再绑定。不能把一个单元的缺口扩大为全片停止规划。
- 连续性同时保留物理与人物状态：位置、持握、形态、场景变化、疲劳、呼吸、关系与情绪不因进入安静段自动复原。

## 最终模板与缺口检查

导演方案供 JIN 审阅；模型正文使用 [统一输出模板](../assets/clean-template.md)。外层固定参考职责、全局要求和逐镜画面／声音／出片要点，内部按任务密度写连续段落。模板不要求固定人数、资产数、负面词或每镜句数。

需要解释字段背后的需求时读取 [注释模板](annotated-template.md)。缺口按以下方式处理：

1. 已确认事实：检索当前材料并直接继承，不重复提问。
2. 导演执行选择：提出能完成当前任务的具体方案，说明必要假设后继续；不把焦段、距离和每个格子都变成问题。
3. 重要故事决定／真实资产不明：说明缺什么、影响哪一步，由 idea-parser 合并最多 3 个关键问题；已确认或已授权的项不重问。

用户要整片全部提示词时，覆盖所有已确定的生成单元，不自行只给第一段并结束。若关键资产未完成，覆盖全片的可完成规划，并列清哪些单元已可提交、哪些仍是草案及具体缺口。用户只要当前段时，仅展开当前段，保留必要前后状态。

## 粗剪与验收

生成前，可用文字分镜或已有图按预估时长做一次顺序检查；用户明确需要预演时再制作，不自动生成媒体。

实际片段齐备后，按真实可用片长核对整片：

- 观众能否理解人物为何行动、选择造成什么后果；
- 开头建立的必要信息是否被承接，揭示是否过早或遗漏；
- 动作接触、对白和反应是否留有可读时间，静默是否仍有叙事作用；
- 空间、动作方向、道具状态、情绪与声场是否跨段连续；
- 音桥起止是否明确；旧镜声音延续到新画面与新镜声音提前进入分别记录；
- 总长与节奏问题应通过保留、缩短、调序建议或局部重做解决，涉及改变获批剧情先确认。

实际影片问题交 failure-diagnostics 定位到故事呈现、镜头、表演、资产、连续性或生成偏差。文字自检不能代替真实成片验收，也不把生成故障当成修改故事的授权。
