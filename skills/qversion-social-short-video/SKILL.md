# Q版社交短视频导演 Skill

这是日常 Q 版 / 拟人化角色短视频的专用分支，优先服务 9:16、约 8–15 秒、动作与情绪驱动的社交媒体内容。

## 默认时长：15 秒（硬规则）

当用户要求生成 Q版社交短视频，但没有明确指定时长时，默认生成 **15 秒**。

- 只有用户明确提出其他时长，例如 8 秒、10 秒或 30 秒，才改变视频时长；
- 不得因为剧情简单、只有一个笑点、成本、节奏判断或模型偏好，自行缩短或延长；
- 用户只提供题材、画面或动作而未提及时长时，仍按 15 秒编排；
- 若目标平台的硬性限制无法生成 15 秒，应先向用户说明限制并确认替代时长，不得静默改成其他秒数；
- 时长确定后，时间轴各段之和必须准确等于该时长。


## 证据基线：不得覆盖 Claude 原经验

开始工作前，读取 `references/claude-original-methodology.md`。

该文件保存长期协作中反复试错、验证、迭代得到的原始方法论。它是本 Skill 的经验基线：

- 不删除其中任何经验；
- 不把尚未验证的问题偷偷改成确定规则；
- 新经验只能以增量方式补充；
- 若新方法与原经验冲突，先记录冲突与样本，不直接覆盖原文；
- 用户提供新的生成结果时，保留“提示词 + 成片反馈”作为证据，再决定是否升级规则。

下面的“当前生产经验”来自用户已经实际生成、并明确反馈为喜欢或爆款的样本。它们属于当前系列的高价值增量证据，但不意味着所有题材都必须套同一个结构。

## Sera 当前角色位置：默认后景 OB / IP 活水印

开始当前 Q版社媒视频工作时，同时读取：

`references/sera-background-ob-watermark.md`

这是用户最新确认的 Sera 使用方式，**优先于本 Skill 里较早的“Sera 默认属于活动角色”表述**。历史案例与旧模板仍保留原样作为当时的证据，不回写历史。

当前默认：

- Sera 不再自动进入每条视频的主线活动角色名单；
- 若用户提供 Sera 资产，优先把它用作后景 OB / 彩蛋式 IP 水印；
- Sera 可以在后景做自己的轻生活动作，例如喝东西、看书、整理东西、坐着发呆、从远处慢慢经过；
- 她不需要静止，也不是半透明 Logo；她是低抢戏的“活水印”；
- 她的背景行为不能推动主事件、改变主事件结果、抢 POV 注意力或开启第二条剧情线；
- 不强制每个镜头都看见 Sera，近景或 POV 转向时允许她自然离开画面；
- 如果用户明确要求某条视频里 Sera 重新参与主剧情，再单独恢复她的动作、互动和声音设定。

写实体数量时必须区分“参与主线动作的角色”和“后景 OB”。例如不要写“画面中只有糯糯一个角色”却又让 Sera 出现在后景；应写“参与主线动作的角色只有糯糯，Sera 仅作为后景 OB 存在”。

## 15 秒完整提示词写法基准

当用户要求生成当前 Q 版系列的 **15 秒完整视频提示词**，尤其要求“按照欢迎回家优化版的写法”时，读取：

`references/welcome-home-15s-template.md`

这份文件保存用户指定的完整 15 秒《欢迎回家》提示词，不要因为当前聊天上下文不足而只依赖摘要。参考它的完整输出组织、动作细化密度、逐段音频、角色差异与失败保险，再根据当前题材改写内容；不要机械复制《欢迎回家》的具体剧情。

### 模板用于学习密度，不用于制造冗长

完整模板提供的是**信息组织与控制密度基准**，不是要求每条 15 秒提示词都复制相同字数、段落数量或禁止项数量。

生成最终提示词时：

- 已经在时间轴里清楚表达过的事实，不为了“保险”在角色要求、动作要求和反向约束里重复三四次；
- 反向约束只保护当前视频真实容易崩的剧情事实、角色身份、道具连续性、一次性动作、时序和 POV 因果；
- 不要写与当前题材无关的禁止项。例如当前视频根本没有某个角色，就不要额外写“不要出现该角色”，除非已有实际生成证据表明模型会错误召回它；
- 不要在最终视频提示词里写“和欢迎回家不同”“不要像某旧案例”之类对模板或旧案例的比较说明；直接告诉视频模型当前画面要发生什么；
- 如果一个约束已经能由更具体的正向动作描述解决，优先保留正向描述，不再堆重复否定词；
- 保持足够细节来控制关键动作，但字数应服务生成稳定性，不把“写得更长”当作“控制得更好”。

最终目标是：**保留《欢迎回家》那种动作过程、角色差异、音频时序和失败保险的清楚程度，同时删除当前题材不需要的重复信息。**

## 核心导演原则

## 轻量资产默认值（硬规则）

普通 8–15 秒 Q版日常视频若已有本条真正出镜角色的身份资产，默认**直接写视频提示词**，不再制作组合场景图、动作姿态图、道具图或故事板。

以下内容属于可变层，由提示词生成：

- 普通卧室、客厅、玄关、门、床等生活空间，只写动作成立所需的必要锚点；
- 枕头、杯子、拖鞋、食物等没有独特世界观设计的日常道具；
- 敲门、开门、指向、转头、点头、走路、跑动、拥抱、拿取、放下等普通动作；
- 水汪汪的眼睛、开心、期待、犹豫等表情与微表演；
- POV 转向、摄影机上下晃动、轻微手持感和简单焦点变化。

不要把动作时间线中的每个阶段变成一张静态资产。不要因为三人同框、存在物理接触或摄影机需要转向，就自动交给 asset-director 或 astra-video-asset-prep。

仅在以下情况之一明确成立时，才评估额外资产：

- 用户主动要求制作该资产；
- 独特角色身份、世界观场景、专属道具或 VFX 的外观无法仅靠文字稳定定义；
- 镜头包含极端大姿势、高难度身体力学或复杂多人 blocking，且关键结果无法从现有资产推断；
- 需要精确跨镜继承构图／空间／姿态；
- 已有实际生成失败证明某个具体视觉事实反复漂移。

提出额外资产时必须说明“它只锁什么”以及“没有它具体会失败在哪里”。没有这个答案，就保持轻量流程。

把提示词当作**分镜脚本 + 导演笔记**，而不是静态画面说明。

优先描述角色和画面**如何从一个状态过渡到下一个状态**。每个关键动作都尽量包含：

1. **发力起点**：动作开始前的身体信号；
2. **过渡状态**：动作真正发生时的中间过程；
3. **结果状态**：动作完成后的衰减、停顿或稳定姿态。

不要用“跑过去、抱住、撞倒、开心、震惊”这种结果词单独承担动作控制。

短视频不是把“大故事”压缩到 10–15 秒，而是让一个小事件拥有完整、可读、可记住的状态弧线。

## 固定层与可变层

### 固定层：同一角色系列尽量保持稳定

固定层可直接沿用同一角色已验证的版本，包括：

- 拍摄 / 成像风格；
- 镜头类型；
- 角色比例、描边、上色、发型等辨识特征；
- 角色专属拟声词、说话方式或发声权限；
- 角色音色；
- 已验证且不需要随剧情变化的角色身份描述。

不要为了“优化文案”每天重新改写固定层。若已有版本稳定，优先复用。

### 当前社媒系列已验证的实拍融合固定方向

当用户继续制作目前这组“Q版角色进入真实生活空间”的社媒视频时，可优先复用以下视觉逻辑，而不是每天重新发明：

- 真实手机实拍质感；
- 第一人称 POV 手持手机；
- 镜头只保留轻微、自然的人体晃动；
- 真实居家、门廊、玄关等现实环境光；
- Q版角色不是贴纸或平面叠图，而是现实空间中的 2.5D 赛璐璐实体；
- 有圆润实体厚度、清晰粗黑描边；
- 头发为简化动漫块面，不转成毛茸茸写实毛发；
- 扁平上色、颜色干净、低阴影；
- 角色受真实场景光照影响，并有接地阴影、接触阴影、重量感与真实接触；
- 参考图为二次元 Q版 CG 时，不把角色真人化，不生成真人皮肤质感与真人五官。

具体头身比、体型、服装和特殊身体特征仍以当前角色参考和项目设定为准，不从一个角色样本泛化到全部角色。

### 当前角色发声配置

当前菲比 / 糯糯 / Sera 系列默认都**不说正常完整人类语言**，只使用自己的拟声词体系，除非用户明确改变设定：

- 菲比：`菲比啾比` / `菲比`
- 糯糯：`糯糯`
- Sera：`Sela`

当前常用音色方向：

- 菲比：元气、活泼、可爱；
- 糯糯：软糯、轻柔、二次元可爱音色；
- Sera：温柔、安静、软萌。

不要把三人的拟声词互换。

注意：上面的 Sera 声音配置只在用户明确让 Sera 重新成为活动角色时使用。Sera 作为后景 OB / IP 活水印时，默认不为她分配主线台词或拟声词。

### 作者层与视频提示词层必须分开

用户在构思阶段写 `~`、`！`、重复音节等，首先是给**写提示词的 AI**理解情绪强弱、拉长、撒娇、兴奋或短促感的作者层标记。

最终交给视频模型的提示词：

- 可以直接保留最终确定的拟声词文本；
- 可以直接写“兴奋地喊”“满足地拉长声音”“轻轻地发出”等实际表演方向；
- **不要再解释**“`~` 代表拉长音”“`！` 代表兴奋”这种元说明；
- 不把写提示词的方法论、符号解释或作者备注塞进最终生成提示词。

### 可变层：每条视频重新导演

每次重新设计：

- 地点与必要空间锚点；
- 时间、光线氛围；
- 本条视频真正会使用的关键道具及必要位置关系；
- 动作阶段；
- 情绪结构；
- 角色行为差异；
- 音频时序与空间距离；
- 结尾记忆点。

## 场景空间：只写动作成立所需的必要锚点

当前爆款 / 高满意样本显示，真实居家短视频不需要把整个空间变成建筑平面图。

只写**会影响动作、视线、移动或道具连续性**的空间事实。例如：

- 玄关欢迎：门、拖鞋、钥匙盘；
- 披萨外送：前门透明玻璃、门垫、石板小路、远处大门；
- 睡眠照顾：沙发、被单、电视及其作为光源 / 噪音源的存在。

不要无意义规定所有家具精确左 / 右 / 前 / 后位置。空间描述越多不等于越稳定；只有在某个位置关系会决定动作是否成立时才写死。

空间写作检查：

1. 角色从哪里进入 / 离开？
2. POV 为什么能看见目标？
3. 关键道具在哪里，角色怎样接触到？
4. 后续动作需要保留哪条移动路径？

除此之外允许模型自然补全生活空间。

## 15 秒默认节奏

当用户没有另行指定且目标约为 15 秒时，优先从 **5–7 个动作 / 状态阶段**构建，不等于强制 5–7 个剪辑镜头。

一种可用思考方式：

```text
建立状态 / 预期
→ 第一次行动
→ 发生阻力、异常或第二次行为
→ 升级 / 反转 / 情绪加深
→ 角色即时反应
→ 收尾动作
→ 稳定定格 / 记忆点
```

允许合并节点。若内容简单，不为了凑数量硬塞事件。

约 8–10 秒时，优先单一情绪弧线和 3–5 个动作阶段；不要机械加入完整反转。

30 秒以上优先拆为多个独立镜头，让每镜服务单一叙事目的。

### 从 10 秒加强到 15 秒时，不要机械增加剧情

当前欢迎回家样本说明：一个 10 秒结构已经有效时，延长到 15 秒优先做的是：

- 补足搬、跑、滑、接、摸、放下等动作的中间状态；
- 增加角色之间的真实接触或 POV 回应；
- 给微表情、犹豫、确认、减速、放松留时间；
- 让每个角色的行为选择更完整。

不要为了“15 秒必须有反转”硬加与主题无关的新剧情。

## 动作写法

关键动作优先写成因果链。例如：

```text
小短腿蹬地加速
→ 身体前倾
→ 双臂张开
→ 接触瞬间摄影机受到轻微反作用后仰
→ 手臂环抱收紧
→ 身体张力逐渐释放并稳定下来
```

重点不是词多，而是：

- 中间状态不能消失；
- 接触动作要有物理反馈；
- 动作结束要有衰减，不要瞬间冻结；
- 同一时刻不要让角色、摄影机、台词和环境同时发生多个高强度事件。

### 小体型 Q版角色要写重量与尺寸造成的动作结果

当前系列中的“巴掌大小 / 小团子”角色，魅力经常来自尺寸与物理反差。若道具相对角色很大，明确表现：

- 抱起后身体微微后仰；
- 小跑时左右摇晃；
- 踮脚才能放下；
- 放稳后才松手；
- 接过钥匙等物件时身体轻轻下沉。

不要只写“拿着大拖鞋”“拿着钥匙”，要让物体的大小和重量进入角色动作。

## 多角色：用行为选择区分性格

多角色不要主要依赖台词区分。优先让性格体现在行为选择。

当前欢迎回家高满意样本提供了一个很有效的三角色分工例子：

- 活跃角色通过蹦跳、抢先行动、滑铲、争摸等直接动作制造能量；
- 软糯 / 照顾型角色通过搬拖鞋、递物、等待表扬、蹭手等动作制造亲近感；
- 克制 / 细心角色通过收钥匙、放回物件、轻微点头、较少抢镜的动作制造温柔收束。

这说明三角色同框时，比“三个人一起冲、一起喊、一起挥手”更有效的方式是：**让每个人对同一目标做不同贡献。**

这些行为分工来自当前角色样本，不应机械复制到所有新角色；但“同一目标、不同选择”可以作为通用方法。

Sera 仅作为后景 OB 时，不把她算进这一段的“多角色主线表演分工”；她只需要保持低抢戏背景行为。

## POV：所有镜头移动都要有原因

真实手机 POV 不是“随机手抖”。

摄影机只因观众 / 拍摄者正在做真实动作而移动，例如：

- 拧钥匙、推门；
- 低头看脚边角色；
- 蹲下摸头；
- 伸手接盒子；
- 抬盒子到镜头前查看；
- 抬头目送角色跑远。

若发生角色扑抱、撞上、拉扯等真实接触，可以让摄影机产生对应的小幅后仰或晃动。

不要添加没有叙事动机的快速摇镜、漂移、突然跳切或“为了电影感”的随机运镜。

## 道具：单主线物件要保持实体连续性

当前披萨外送爆款样本显示，当一条视频围绕一个核心道具推进时，应明确保护这个道具的连续性。

例如“交付”类动作链：

```text
角色持有同一物件
→ 递向 POV
→ POV 双手接稳
→ 角色确认接稳后松手
→ POV 再检查 / 打开同一物件
```

需要时明确：

- 始终是同一个盒子 / 拖鞋 / 钥匙；
- 只交接一次；
- 先接稳再松手；
- 盒内内容数量保持唯一；
- 物件不要复制、变形、换款或突然重新出现在原持有者手里。

道具越承担剧情反转，连续性越重要。

## 台词、拟声词与音频

先确认角色发声权限：

- 可说完整句子；
- 只允许拟声词 / 短音节；
- 不发声，只靠动作、呼吸或环境声表演。

当前菲比 / 糯糯 / Sera 默认属于“只允许专属拟声词”的类型，但 Sera 只有在明确恢复为活动角色时才进入音频分配；后景 OB 状态默认不发声。

多角色尤其在同一 2–3 秒阶段内，不优先安排同时发出大量声音。若需要多角色发声，优先错开；高潮结尾才考虑很短的叠加。

音频必须与动作事件和空间距离绑定。例如：

- 起跑后才发出边跑边喊的拟声词；
- 角色从近处跑向远处时，声音也从近到远；
- 睡眠治愈主题可以完全没有角色拟声词，只保留呼吸、布料、电视、门声等环境与动作声；
- 不用拟声词解释剧情，让视觉动作自己成立。

音频格式可采用：

```text
音频：[角色名] “[精确拟声词]”（真实语气 / 距离变化）
```

最终提示词只保留视频模型需要知道的实际声音，不加入符号方法论说明。

## 三种当前高价值内容结构

以下来自用户实际高满意 / 爆款样本。把它们当作可选结构库，不强制所有视频使用。

### A. 治愈观察 / 照顾型

适合“回家发现角色睡着”等低能量主题。

结构可为：

```text
进入空间并发现安静状态
→ 放轻动作靠近观察
→ 发起一个不打扰角色的照顾动作
→ 中途停顿确认没有吵醒
→ 角色出现微小无意识反馈
→ 处理环境噪音 / 光源
→ 回到角色身上安静定格
```

关键经验：

- 不需要强行反转；
- 张力来自“怕吵醒她”的动作克制；
- 微反馈比大表情重要，例如抓被角、呼吸变化、身体轻轻缩一下；
- 环境声可以承担主要音频叙事；
- 结尾通过关电视、降噪、降低动作强度完成情绪收束。

### B. 交付 → 离场 → 揭示反转型

当前披萨外送菲比爆款样本的有效结构：

```text
奇怪但一眼可懂的角色身份 / 任务出现
→ 单一主道具完成一次交接
→ 角色迅速离场
→ POV 二次检查同一主道具
→ 出现一眼可懂的小反转
→ POV 再抬头看角色远去
```

关键经验：

- 前 1–2 秒就让观众看懂“奇怪身份 / 奇怪任务”；
- 全片围绕一个主道具，避免支线抢焦；
- 角色先离场，再揭示道具里的反转，会产生更好的余韵；
- 反转用视觉证据呈现，不用台词解释；
- 角色从近到远的移动可同时带动声音距离变化；
- 结尾回到角色小小背影，形成完整闭环。

### C. 多角色欢迎回家 / 连续照顾型

当前三角色欢迎回家爆款样本说明：欢迎主题不必依赖反转，可以靠**连续被照顾**形成满足感。

结构可为：

```text
开门即看到角色已经在等待
→ 角色 A 做最直接的照顾动作
→ 角色 B 用更活跃 / 搞笑的方式加入
→ POV 对角色做真实回应
→ 角色 C 用克制、细心的动作补上照顾
→ 三名角色以不同反应接受 POV 回应
→ 形成清楚、温暖的三人结束构图
```

关键经验：

- “欢迎回家”不要只靠挥手或发声，要通过可见的照顾动作发生；
- POV 的摸头、接物等回应能显著增强“我真的回家了”的代入感；
- 三角色分别做不同事情，比同时做同一动作更有角色感；
- 结尾三人并排 / 围住 POV 的稳定构图本身就是记忆点；
- 没有反转也可以成立，只要小奖励动作连续发生。

## 反转与社交媒体记忆点

约 15 秒且内容允许时，可使用：

```text
建立预期 A
→ 实际发生 B
→ 角色反应或视觉证据确认 B
```

反转不是强制项。

先判断内容靠什么成立：

- 靠视觉反差 / 小恶作剧 → 可以使用反转；
- 靠被照顾 / 治愈 / 微表演 → 不强行反转；
- 靠角色动作魅力 → 保持单一弧线也可以。

结尾优先留下一个容易读懂的状态：

- 明确表情 / 姿态；
- 失败后的尴尬停顿；
- 突然安静；
- 角色看向镜头；
- 小动作收尾；
- 远去的小背影；
- 三角色稳定欢迎构图；
- 可自然循环回开头的状态。

## 参考图规则

多张素材必须显式标注 `图1 / 图2 / 图3...`。

每张图至少说明：

- 它是谁 / 是什么；
- 精确锁定什么；或
- 只做氛围 / 道具 / 世界观参考什么；
- 不应继承什么（有高污染风险时）。

多人角色参考尤其明确：

- 图一、图二、图三分别是不同角色时，画面有且仅有这些实体；
- 不重复生成任一角色；
- 不交换脸、发型、服装、配件、身份；
- 不继承参考图白底、原姿势和原构图；
- 参考图是 Q版 CG 时，不因为“真实手机实拍”把角色真人化。

### Sera 后景 OB 资产的参考职责

若当前输入里包含 Sera 资产，而用户没有指定她参与主线剧情：

- 把该图用于锁定 Sera 后景 OB 的身份、外观、发型、服装、比例；
- 在场景设计时利用后景、远景、画面边缘或景深层次放置她；
- 可以给她一个简单、自然、与主事件无关的背景动作；
- 不复制参考图原姿势、白底或构图；
- 不让她因为有角色资产就自动进入主线动作、对话和 POV 互动；
- 不强制每个镜头出现，只在景别允许时自然发挥。

详细规则见 `references/sera-background-ob-watermark.md`。

换角色套用已有动作模板时，区分：

- **角色专属字段**：外观、武器、拟声词等，必须替换；
- **世界观锚定字段**：天气、场景氛围、粒子与特效语言，跟随世界观替换；
- **纯技术字段**：运镜、构图节奏、动作因果结构，可以跨角色复用。

若当前任务需要进一步判断“到底缺什么角色姿态 / 场景 / 面部资产”，交给上层 `asset-director`；本 Skill 不机械索要完整四视图。

## 反向约束与失败保险

不要使用固定超长 negative prompt。先找这条视频**最不能坏掉的剧情事实**，再写少量保险。

优先从以下维度推导：

### 实体数量

例如：

- 画面中只有指定角色和 POV 双手；
- 不出现额外人物或角色分身。

如果使用 Sera 后景 OB，不要用会与画面事实冲突的“只有一个角色”写法；改为分别说明“主线参与角色”与“Sera 后景 OB”。

### 一次性动作

若剧情只允许一次：

- 只交接一次；
- 只滑铲一次；
- 只跑远一次；
- 只把钥匙放回一次。

直接写出来，避免模型重复表演同一动作。

### 道具状态

例如：

- 始终是同一个盒子；
- 盒内始终只有一片披萨；
- 拖鞋不变成其他物品；
- 钥匙不会复制。

### 时序

例如：

- 菲比必须在起跑后才喊；
- POV 必须先接稳盒子，角色才松手；
- 打开盒子确认反转后再合上；
- 后续动作不得提前发生。

### 摄影机因果

写清 POV 只因具体动作而移动，不无故抖动、跳切或换视角。

失败保险的目标是保护**事件逻辑与连续性**，不是堆“高质量、不要畸形、不要错误”这种泛词。

## 日常生成工作流

1. 读取并优先复用当前角色已经稳定的固定层。
2. 确认角色发声权限与固定拟声词。
3. 用一句话确定今天视频的**唯一核心事件**。
4. 选择是否属于已有高价值结构，或需要新结构。
5. 按时长分配动作 / 状态节点。
6. 检查每个关键动作是否具有“发力 → 过渡 → 结果”。
7. 多角色时先分配“谁选择做什么”，再分配声音。
8. 只补动作成立所需的场景与空间锚点。
9. 若有核心道具，检查它是否从头到尾是同一实体、状态是否连续。
10. 检查 POV 的每一次移动是否有真实原因。
11. 编号所有输入参考图并标清职责；若包含 Sera 资产且她不参与主线，则按后景 OB / IP 活水印处理，并只在景别允许时自然放入后景。
12. 检查同一时间片是否信息过载。
13. 从剧情最脆弱的位置推导少量失败保险。
14. 删除作者层元说明，只留下可直接交给视频模型的最终提示词。

## 默认输出结构

按任务需要输出，不强迫所有项目齐全：

```text
生成视频：[时长 / 模型 / 比例 / 成像方式]

[风格与角色固定层]

[参考图职责与实体数量；如有 Sera 后景 OB，单独标注]

场景：[只写必要空间锚点]

0–Xs 画面动作：...
音频：...

X–Xs 画面动作：...
音频：...

...

【反向约束与失败保险】
[只保护本条最关键的数量、物件、时序、身份与摄影机逻辑]
```

动作时间轴的每一段优先描述“状态变化”，不要只是列动作名称。

最终提示词应像用户当前爆款样本一样：**直接、具体、可执行**。不要在成品里解释为什么这样写，也不要放给提示词作者看的方法论说明。

## 失败时怎么改

若成片不理想，不先整份重写。优先找到唯一主故障：

- 动作跳跃 → 补中间状态；
- 结果动作不稳定 → 补动作后的衰减与最终姿态；
- 多角色混乱 → 减少同时动作 / 同时发声，重新分配行为选择；
- 角色漂移 → 恢复已验证固定层与参考图职责；
- Q版角色变真人 → 重申 Q版 CG 身份、2.5D 实体语言与禁止真人五官 / 皮肤；
- 角色像贴纸 → 补重量感、接地阴影、接触阴影和真实场景受光；
- 道具复制 / 换物 → 强化同一实体、一次性交接和状态连续；
- POV 乱晃 → 删除无动机运镜，只保留行为驱动移动；
- 节奏拖沓 → 删除无意义节点，不压缩关键过渡；
- 15 秒内容太平 → 先判断是否缺少更明确的角色行为、奖励节点或视觉反差，再决定是否需要反转；
- 信息过载 → 减少同一时间切片里的声音、动作或镜头事件；
- Sera 后景 OB 抢戏 → 把她移远、降低动作幅度、减少出现镜头，保留主线角色和 POV 为注意力中心。

新生成结果如能证明某条写法稳定有效，记录到后续实验 / 样本文件，不直接修改 Claude 原始方法论。

## 尚未验证：必须继续保留为开放问题

不得把以下问题擅自结论化：

1. 零台词写法对高能量 / 活泼角色的适用边界；
2. “减少台词”与“细化动作”各自对稳定性的独立贡献；
3. 完整反转结构在 8 秒以内的可执行下限；
4. 角色专属、世界观锚定、纯技术字段的自动分类规则；
5. 当前三个高价值内容结构在其他角色 IP 或其他视频模型上的泛化程度。

这些问题应通过后续真实生成样本继续验证。
