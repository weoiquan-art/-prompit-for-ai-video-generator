# Sera 成女形象视频支线

## 给刚读到本 Skill 的 AI：你现在要做什么

读完本 Skill 后，不要停在“知道 Sera 长什么样”。你的任务是帮助创作者把 **Sera 成女 IP 从想法推进到可生成的视频方案**。

先判断用户当前处于哪一步，然后只推进当前步骤：

```text
A. 还在定义 Sera 这个 IP
→ 帮用户把角色人格、世界、关系、能力、内容方向说清楚。

B. 已经有一个短剧 / 短视频想法
→ 先整理核心事件与每一段主要展示任务，不急着直接写最终视频提示词。

C. 已经决定采用“2张人物资产 + 4张分镜资产”
→ 先把4个镜头各自要展示的动作、构图与结束状态定义清楚；再生成4张16:9线稿分镜资产。

D. 6张资产已经确认
→ 由当前视频导演 AI 根据2张人物资产 + 4张分镜资产，生成约11秒的正式视频提示词。

E. 需要进一步降低复杂镜头试错成本
→ 再考虑 Blender 3D previs；不要默认每条视频都必须进 Blender。

F. 已经生成成片
→ 对照原提示词、分镜资产 / Blender 预演与成片，记录成功、失败和偏差；未经用户批准，不自动升级成规则。
```

### 当前第一优先事项

如果用户正在制作具体视频，就先推进当前视频，不因为 IP 尚未全部定义而阻断制作。

用户表达还没有完整时，**允许并应该询问真正缺失的意思**。不要因为想让流程“完整”就自行猜测剧情、世界观、角色关系、动作或最终目的。

### 当前职责边界

本工作流里：

- **当前视频导演 AI（本 Skill 的使用者）负责：** 和用户确定故事 / 镜头任务、设计4个分镜内容、最后生成正式视频提示词；
- **Astra 或其他生图工具负责：** 根据已经确定的分镜内容，把动作与构图生成成分镜资产；
- **Blender 负责：** 仅在确实需要时验证复杂空间、相机、走位和连续运动；
- 不把“让 Astra 写最终视频提示词”当成默认职责。

### 你的交付目标

根据当前阶段，最终应交付下面其中一种，而不是全部一起输出：

- `Sera IP 设定卡`；
- `短剧 / 短视频核心事件`；
- `4镜故事板内容方案`；
- `4张分镜资产生成说明`；
- `Blender 预演任务说明`；
- `可直接投喂视频模型的最终提示词`；
- `成片复盘与下一轮修改建议`。

本支线不是为了把所有步骤一次写完，而是让 Sera 的生产流程**一层一层确认后再往下走**，减少昂贵的视频试错。

## 支线定位

这是 Sera IP 的**成女 / 非Q版视频支线**。

它与 Q版 Sera 属于同一个 IP 的不同视觉形态，但两条线必须分开处理：

- Q版 Sera 继续使用原来的 Q版比例、拟声词、生活化社媒逻辑；
- 成女 Sera 使用本支线的角色比例、镜头语言、表演方式和视觉基准；
- 不因为调用本支线，就修改或覆盖 Q版 Sera 的既有设定；
- 只有用户明确说“成女 Sera / 非Q版 Sera / adult Sera”时才进入本支线。

当前目标不是只做一条一次性视频，而是逐步建立一套**可持续复用的 Sera 成女形象视频生产线**：角色形象稳定、资产可复用、短剧可持续扩展、提示词方法可通过真实成片继续学习。

## Sera IP：先把“她是谁、为什么值得一直拍”逐步说清楚

这个支线不只是在保存外观。AI 还要帮助创作者逐步回答：

> **Sera 是一个什么样的人？观众为什么会想继续看她？她适合不断发生什么样的故事？**

但不要求在第一条视频前一次性写完完整 IP 圣经。用户当前没有 IP 塑造经验，因此允许采用“边做短片、边验证角色”的方式：

```text
先确定一个明确的人格核心
→ 做一条小视频验证
→ 看哪些行为真的像 Sera
→ 用户确认后再沉淀成人设事实
→ 再做下一条
```

当前已经明确的创作意图：

- 用户不只想让 Sera 停留在 Q版日常内容；
- 想发展 Sera 的**成女版本**，用于更完整的角色短剧、角色短视频，以及可能的剧情 / 动作展示；
- 希望成女 Sera 保持稳定的独立视觉身份，而不是每次生成都重新设计；
- 希望逐渐形成可持续扩展的 Sera IP，而不是只追求一条漂亮 PV；
- 希望借助分镜资产、必要时的 Blender 预演与可复用资产，减少正式视频生成的试错成本；
- 提示词导演方式希望接近已确认的“贤者式”分段展示任务写法；
- 当前第一轮优先尝试约 11 秒、4 个连续分镜，而不是一开始就上 30 秒。

其余人格、世界观、关系与能力必须继续由用户确认，不由 AI 自行补成官方设定。

## 视频提示词写法：沿用已确认的“贤者式”展示任务思路

用户指定：成女 Sera 的视频提示词写法，优先沿用此前借鉴的“贤者视频提示词风格”。

目前在仓库中可直接作为已确认学习证据的是：

`../../../sample-learning/references/combat-video-0-15-display-task-case.md`

该案例只确认了 0–15 秒范围。当前可以继承的不是它的具体秒数、战斗动作或固定镜头，而是这种导演思路：

> **先决定每一个时间段主要给观众看什么，再写这个时间段的机位、景别、动作过程和结束状态。**

例如一段 Sera 视频可以分别承担：

- 先交代空间关系；
- 再展示 Sera 本人或某个能力 / 道具；
- 再把注意力交给新的信息；
- 再展示威胁、变化或情绪逼近；
- 最后给 Sera 一个完整反应过程与有记忆点的结束画面。

这只是“展示任务”的组织方式，不是固定五段模板。根据题材可以增减、重排。

### 每个时间段优先写清楚

1. **这一段的主要展示任务**：观众此刻最该看什么；
2. **景别与机位**：全景 / 中景 / 近景 / 特写，正面 / 侧面 / 背面 / 过肩等；
3. **画面主体关系**：谁在前景、中景、后景，谁占画面主要比例；
4. **动作过程**：准备 → 发生 → 接触 / 变化 → 结果；
5. **结束状态**：这一段结束时人物、道具、力量或空间处于什么状态；
6. **声音**：只有当前镜头真正需要时才写。

不要为了“电影感”堆很多抽象术语。镜头术语的作用是让视频模型知道**这一刻要怎么展示 Sera**。

## 六张输入资产工作流：当前首轮默认

这是当前 Sera 成女首轮短片已经确认的生产方式。

### 六张图分别做什么

```text
图1：Sera 成女三视图 / 全身角色资产
图2：Sera 成女面部近景角色资产
图3：镜头1分镜资产
图4：镜头2分镜资产
图5：镜头3分镜资产
图6：镜头4分镜资产
```

一句话总纲：

> **人物资产负责锁“她是谁”，分镜资产负责锁“这一镜看什么”。**

图1、图2负责角色身份一致性；图3–图6负责4个镜头各自的动作、机位、构图和空间关系。

### 4张分镜资产的默认形态

当前参考此前“贤者 / 未来魏与现在魏”工作流中使用的故事板资产形式，Sera 首轮默认采用：

- **16:9 横构图**；
- **线条绘画 / storyboard / key pose 草图**；
- 可以使用少量灰阶或简单色块帮助区分人物，但不追求成品插画；
- 一张图只服务一个镜头；
- 优先把人物位置、动作姿势、景别、角度、前后关系画清楚；
- 不要求背景精修，不要求材质和最终灯光完全成立；
- 分镜资产是视频生成的导演 / 构图参考，不是最终画面风格参考。

如果 AI 生成的分镜变成高完成度人物海报、竖版角色写真、精修成片截图感，应视为**方向跑偏**，需要回到 16:9 线稿故事板。

### 为什么每张分镜要独立

图3–图6不是一张“整条视频的共同参考图”拆成四份。它们必须逐镜承担职责：

```text
图3 → 只负责镜头1要看什么
图4 → 只负责镜头2要看什么
图5 → 只负责镜头3要看什么
图6 → 只负责镜头4要看什么
```

视频提示词里也要逐张说明参考责任，不把某一张分镜的姿势、构图、角色位置自动继承到后面的镜头。

若分镜素材本身来自其他案例或带有占位人物，它只用于所声明的动作 / 构图职责；不要继承无关角色身份、服装、面具、字幕或其他案例元素。

### 先设计动作，再生成分镜资产

不要为了凑够4张图，先让生图模型随便生成4张漂亮画面再倒推剧情。

正确顺序：

```text
用户的短片意思
→ 当前视频导演 AI 与用户确认还没表达完的部分
→ 确定核心事件
→ 拆出4个镜头各自的“主要展示任务”
→ 为每镜定义动作、人物位置、机位 / 景别、结束状态
→ 再让 Astra / 当前可用生图工具生成对应的16:9线稿分镜资产
→ 用户检查并单独修改错误镜头
→ 4张分镜都确认后，与图1、图2合并成6张输入资产
→ 当前视频导演 AI 写正式视频提示词
```

### 分镜不是必须手画，也不是必须 Blender

4张分镜资产可以：

- 直接由当前可用的图像生成模型生成；
- 由 Astra 生成（若当时具备合适的图像生成能力）；
- 用户手绘后再由 AI 整理；
- 必要时从 Blender previs 输出关键帧。

首轮优先选择**最轻、最快、能把动作与构图表达清楚的方法**。如果直接生图已经能得到正确的线稿分镜，就不为了流程完整而增加软件步骤。

## 四拍镜头组：贤者案例中的节奏参考

用户重新提供的贤者工作流画面中，有一类明确写法：

> 四拍镜头组，约 8 秒，4 个连续分镜。每个分镜约 2 秒，动作后都有半拍停顿，像二维动画 key pose 卡鼓点。

并出现类似“过去魏 / 现在魏”的空间与视觉关系交代：用简化线条分镜明确近处人物、远处人物以及视线 / 镜头进入关系。

当前对 Sera 可以学习的是这种**分镜资产的表达与节奏方式**，不是机械复制人物、剧情或固定秒数：

- 先明确四拍分别展示什么；
- 每拍给动作一个可读的关键姿势；
- 需要时让动作完成后有短暂停顿，让画面读得清；
- 分镜图优先把 key pose 与空间关系画出来，而不是追求插画完成度。

Sera 首轮目标约 11 秒，因此可以保留“4个连续分镜”的思路，但各镜秒数根据实际动作重新分配，不强制每镜正好 2 秒。

## 故事板与 Blender：不是二选一

用户此前的故事板工作流是：

```text
先有粗略想法 / 手绘故事板
→ 再由 AI 丰富画面与导演细节
→ 最后交给视频模型生成
```

成女 Sera 支线准备把这套方法扩展成更可验证的版本。

### 2D 故事板负责“先想清楚画面”

故事板主要解决：

- 这一镜发生什么；
- 人物大概在哪里；
- 大概什么景别 / 角度；
- 前后事件顺序；
- 哪几个画面值得成为关键帧。

故事板可以来自：

- 用户自己手绘；
- AI 根据用户与当前视频导演已经确认的镜头任务生成；
- 两者结合。

如果 Astra 当前确实具备可用的图像 / 故事板生成能力，可以让 Astra 帮忙生成**粗略故事板资产**。但本 Skill 不预设 Astra 一定拥有某个具体能力；实际使用前根据当时可用功能决定。

AI 生成的故事板仍然只是**构思与沟通 / 视频参考资产**，不是空间关系已经被严格验证的证明。

### Blender 负责“把故事板变成可检查的 3D 预演”

这里的 Blender 第一目标不是马上制作电影级最终精模，而是做 **3D storyboard / previs（预演）**。

它主要验证：

- 摄像机到底放在哪里；
- 焦段 / 视角改变后人物大小关系是否成立；
- Sera 与场景、对手、道具之间的实际距离；
- 前景 / 中景 / 后景是否真的能同时成立；
- 角色动作姿势和朝向；
- 一段镜头移动是否会穿模、遮挡或失去主体；
- 连续镜头的方向与空间是否连得起来。

因此早期 Blender 预演允许：

- 简化模型；
- 基础材质；
- 粗略场景块面；
- 简化灯光；
- 用占位角色 / 已有角色模型验证构图；
- 优先保证摄像机、空间、动作与时间，而不是先追求最终渲染质量。

### 推荐的当前实验链路

```text
Sera IP / 当前短剧想法
→ 拆成4段“主要展示任务”
→ 直接生成 / 手绘4张16:9线稿分镜资产
→ 用户确认分镜
→ 简单镜头：直接进入正式视频提示词
→ 复杂镜头：再用 Blender 做3D预演
→ 输出关键帧 / 简单 animatic 或预演视频
→ 用户检查空间、机位、动作、角色展示是否正确
→ 最后由当前视频导演 AI 写正式视频生成提示词并进入 Seedance
```

这不是强制流水线。如果某条视频非常简单，二维故事板已经足够，就不为了流程完整而强制进入 Blender。

反过来，如果某条视频存在复杂空间、战斗、多人调度、特殊机位或连续运镜，Blender 预演的价值会更高。

## Astra 在这里的角色

当前不要把 Astra 单一理解成“帮我建模”的工具。它在这个实验里可以有三个可能职责，实际用哪个取决于当时能力与测试结果：

```text
1. Storyboard Asset Assistant
   根据已经确认的4个镜头任务，生成16:9线稿分镜资产。

2. Blender Assistant
   把已确认分镜、角色设定和镜头要求翻译成 Blender 场景、相机、blocking、脚本或建模任务。

3. Asset Assistant
   帮助制作或调整真正可复用的 Sera 角色 / 场景 / 道具资产。
```

但**正式视频提示词默认由当前视频导演 AI 负责生成**。

优先顺序由问题决定：

- **镜头内容还没确定** → 先和用户讨论，不让 Astra 自己猜；
- **镜头已经确定，只缺分镜图** → 直接生成4张16:9线稿分镜；
- **知道画面但不确定空间 / 相机是否成立** → 再用 Blender 预演；
- **画面与预演都成立，但角色资产不稳定** → 再投入更完整的模型 / 材质 / Rig。

不要一开始就做最昂贵、最复杂的资产。

## 当前首轮视频方向：约 11 秒 / 4 镜
