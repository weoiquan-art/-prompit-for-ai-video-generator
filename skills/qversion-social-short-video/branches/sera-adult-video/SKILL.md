# Sera 成女形象视频支线

## 支线定位

这是 Sera IP 的**成女 / 非Q版视频支线**。

它与 Q版 Sera 属于同一个 IP 的不同视觉形态，但两条线必须分开处理：

- Q版 Sera 继续使用原来的 Q版比例、拟声词、生活化社媒逻辑；
- 成女 Sera 使用本支线的角色比例、镜头语言、表演方式和视觉基准；
- 不因为调用本支线，就修改或覆盖 Q版 Sera 的既有设定；
- 只有用户明确说“成女 Sera / 非Q版 Sera / adult Sera”时才进入本支线。

当前目标不是只做一条一次性视频，而是逐步建立一套**可持续复用的 Sera 成女形象视频生产线**：角色形象稳定、资产可复用、短剧可持续扩展、提示词方法可通过真实成片继续学习。

## 成女 Sera 的当前视觉身份

当前成女 Sera 应保持：

- 二次元动画 / 高质量角色 CG 身份；
- 非真人化；
- 纤细成女比例；
- 超长双马尾与大型耳机是高辨识度轮廓；
- 白、深绿、黑、金属装饰构成主要服装色彩关系；
- 整体气质偏安静、克制、清冷、精致。

不要把“安静、克制、清冷”自动理解为每条视频都面无表情。表情与动作仍然根据剧情决定，只避免无理由的夸张卖萌或失去角色气质。

## 视频提示词写法：沿用已确认的“贤者式”展示任务思路

用户指定：成女 Sera 的视频提示词写法，优先沿用此前借鉴的“贤者视频提示词风格”。

目前在仓库中可直接作为已确认学习证据的是：

`../../sample-learning/references/combat-video-0-15-display-task-case.md`

该案例只确认了 0–15 秒范围。当前可以继承的不是它的具体秒数、战斗动作或固定镜头，而是这种导演思路：

> **先决定每一个时间段主要给观众看什么，再写这个时间段的机位、景别、动作过程和结束状态。**

例如一段 Sera 视频可以分别承担：

- 先交代空间关系；
- 再展示 Sera 本人或某个能力 / 道具；
- 再把注意力交给新的信息；
- 再展示威胁、变化或情绪逼近；
- 最后给 Sera 一个完整反应过程与有记忆点的结束画面。

这只是“展示任务”的组织方式，不是固定五段模板。根据题材可以增减、重排。

### 每个时间段优先写清楚

1. **这一段的主要展示任务**：观众此刻最该看什么；
2. **景别与机位**：全景 / 中景 / 近景 / 特写，正面 / 侧面 / 背面 / 过肩等；
3. **画面主体关系**：谁在前景、中景、后景，谁占画面主要比例；
4. **动作过程**：准备 → 发生 → 接触 / 变化 → 结果；
5. **结束状态**：这一段结束时人物、道具、力量或空间处于什么状态；
6. **声音**：只有当前镜头真正需要时才写。

不要为了“电影感”堆很多抽象术语。镜头术语的作用是让视频模型知道**这一刻要怎么展示 Sera**。

成女 Sera 视频优先使用以下模块，但按任务需要取舍，不强迫全部出现：

```text

【参考图说明】
【画面风格】
【场景 / 空间关系】

【0–Xs｜主要展示任务】
画面动作：...
音频：...

【X–Xs｜主要展示任务】
画面动作：...
音频：...

...

【表演要求】
【必要连续性 / 失败保险】
```

最终提示词要直接、具体、可执行。不要在成品里解释方法论，也不要拿当前视频与旧案例比较。

## 表演方向

成女 Sera 的表演优先依赖：

- 眼神变化；
- 头部和肩颈的小幅动作；
- 手部动作；
- 转身、停顿、减速；
- 双马尾、衣摆、饰品跟随身体产生的次级运动；
- 角色与道具 / 环境之间的真实接触。

如果题材是高能量动作或战斗，可以明显提高动作幅度；如果是角色展示、情绪短剧或日常片，则不为了“有戏”强行加入大动作。

## 当前 30 秒方向

用户目前希望尝试 **Seedance 2.5、约 30 秒** 的 Sera 成女短剧 / 短视频。

30 秒不要求把一条 15 秒结构机械拉长。优先先确定：

- 整条视频只有什么核心事件；
- 哪些时间段用于建立空间 / 人物；
- 哪些时间段用于推进事件；
- 哪些时间段用于 Sera 的关键展示；
- 最后用什么画面完成收尾。

在真正开始写 30 秒视频前，应先与用户把 Sera IP 的内容定位、角色关系、世界观与本条视频目标确认清楚。

## 资产生产计划：Astra → Blender → 视频（当前为实验意图）

用户希望在直接消耗大量视频生成次数之前，先尝试建立更稳定、可复用的角色资产流程：

```text
Sera 成女参考图
→ 尝试使用 Astra 辅助 Blender 建模 / 资产制作
→ 得到可复用的 Sera 3D / Blender 角色资产
→ 将资产用于后续视频生成或视频工作流
→ 减少反复从二维参考重新猜角色外观造成的浪费
```

这是用户当前希望探索的**生产实验方向**，不是已经验证成功的固定规则。

在没有真实测试结果前：

- 不假定 Astra 一定能完整解决 Blender 建模；
- 不假定 3D 资产一定比二维参考更稳定；
- 不把尚未测试的工作流写成强制流程；
- 后续保留“输入资产 → 生成过程 → 成片结果 → 失败点”作为证据，再决定是否升级为正式方法。

## 仍需创作者确认的 IP 信息

在开始写第一条正式 30 秒成女 Sera 短剧前，至少确认：

- 成女 Sera 与 Q版 Sera 是“同一个角色的不同表现形态”，还是不同时间线 / 不同世界版本；
- Sera 的核心人格是什么，哪些行为绝对像她，哪些行为不应该发生；
- 她处于什么世界：现实、近未来、幻想、战斗世界或混合世界；
- 你最想让观众记住 Sera 的哪一个核心魅力；
- 成女系列主要做什么：剧情短剧、角色 PV、日常、动作 / 战斗、情绪片，还是混合；
- 她是否说正常语言，声音 / 台词设定是什么；
- 是否有固定能力、武器、职业、身份、关系角色；
- 30 秒内容更看重“故事完整”还是“角色展示”；
- Astra / Blender 资产最终准备承担什么：角色一致性、动作预演、场景预演、直接作为视频输入，或其他用途。

这些信息确认后，再把真正稳定的 Sera IP 设定写进本支线。

## 治理

- 用户已经明确的信息可以进入本支线；
- AI 从新案例里推导出的规则必须先提出给用户过目；
- 不把一次生成成功自动升级成全局规则；
- 不把 Q版 Sera 的行为、声音、比例自动搬到成女 Sera；
- 不把成女 Sera 的新设定反向覆盖 Q版 Sera。
