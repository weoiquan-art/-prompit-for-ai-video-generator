# Asset Director

只判断：

1. 当前镜头是否真的缺资产；
2. 缺哪一种资产；
3. 每份资产只锁什么；
4. 怎样交接给 `$jin-gpt-image-director`。

本 Skill 不写生图 Prompt、不设计 Blender 制作步骤，也不直接生成或编辑视觉资产。

## 默认结论：普通内容先不新增；独特场景必须先检查

已有身份资产加清楚的视频 Prompt 对普通日常内容通常已经足够。以下内容默认留在视频 Prompt：

- 普通走、跑、坐、拿、递、抱、指向、敲门、开门、回头、点头与简单接触；
- 表情、视线、呼吸、停顿、反应先后和完整动作过程；
- POV 转头、摄影机点头、轻微手持与简单运镜；
- 没有独特设计要求的普通房间、门、床、杯子与生活道具；
- 为时间控制写出的多个动作阶段。

动作存在不等于需要动作资产；道具出现不等于需要道具资产；**普通日常地点**发生在某处也不等于必须生成场景资产。

但如果当前地点是专属世界、专属建筑、文明空间、剧情关键地点，或镜头动作依赖明确的内外关系、地标、门墙结构、通道、平台等空间事实，则必须先检查是否已有可用 Scene Plate。没有时，场景资产是基础资产候选，不应因为“最小资产原则”被默认跳过。

## 新增资产门槛

每一项新增资产必须同时回答：

1. **锁什么：**必须稳定的具体可见事实是什么？
2. **为何文字不够：**现有资产与 Prompt 为什么无法承担？
3. **失败在哪里：**没有它会破坏哪个关键结果？
4. **如何使用：**目标平台或实际制作流程怎样使用它？

任一项无法回答，结论为“当前无需补充”。用户已限定资产范围时，不自行扩大清单。

## 资产分类（硬规则）

### 场景资产／Scene Plate

- 必须是无人、无任何角色的干净环境底图；主角、配角、群众都不出现。
- 只锁地点结构、内外关系、地标、材质、基础光线与必要环境状态。
- 不承载人物身份、站位、姿态或表演。
- 对独特世界场景／剧情关键场景，Scene Plate 不是可有可无的“美术参考”，而是用来防止视频模型临时重解释空间与建筑结构的基础载体。
- 门、墙、桥接点、通道、平台等若属于建筑／环境结构，默认和场景一起锁，不拆成独立道具资产；只有其自身存在独立专属设计、需要脱离场景复用或近距离单独展示时才拆分。

### 角色资产

- 独立锁角色身份、脸、发型、身体比例、服装与本镜真正可见的角度。
- 不机械要求三视图或四视图；本镜只见侧背轮廓时，可以只需要相应角度。
- 场景底图不能代替角色身份资产。

### 道具／VFX 资产

只有独特造型、结构、材质、连接方式或运动形态无法靠文字稳定表达时才补。普通可推断物件不自动资产化。

### 中心事件承载结构

普通的门、桥、墙体、载具或建筑装置，一旦成为中心事件的承受体，就重新判断资产需求。出现以下任一情况时，不再按普通背景处理：

- 事件是否成立取决于它的具体结构、连接方式或失效路径；
- 同一对象会从不同景别或角度被清楚看见；
- 完整状态、变化过程和结果状态必须保持为同一对象；
- 模型若把“破坏”误做成普通开启、替换或复原，会改变故事事实。

优先补一份无人、结构清楚的**完整初始状态 Scene Plate**，把该结构与周围环境、尺度、材质、连接点和空间关系一起锁定。不要因为中心事件发生在“门”上，就默认再制作一张独立门资产。

不要自动再做破损版本；只有特定破口或损伤必须跨后续生成精确继承，且实际尾帧无法承担时，才补结果状态资产。独立对象资产只在该对象确实需要脱离场景单独控制时再判断。

### 故事板／镜头关键帧／白膜／Previs

这类资产可以包含代理人形、角色占位、站位、大姿势和组合关系，因为它们锁的是**镜头空间与构图**，不是可复用场景底图。

适合：

- 多角色前后关系或朝向容易漂移；
- 景别、机位、人物占比必须先验证；
- 巨大尺度关系、遮挡或动作通道复杂；
- 高成本镜头需要先验证 blocking；
- 高难度身体动作需要动作参考或 Mocap。

即使使用这类资产，视频导演仍保留人物 screen-left／screen-right、前中后景、距离、朝向、视线、移动路径和摄影机一侧等最终调度责任。

### 连续性资产

精确动接优先使用上一镜实际结尾帧。没有实际帧时，记录连接物、位置、方向、速度、摄影机和环境状态，不把计划状态冒充生成结果。

## 平台无法使用白膜时

不让流程卡住：

- 白膜可以只作为内部导演／预演辅助；
- 平台能读静态图时，输出白膜关键帧或线稿分镜；
- 平台无法读取任何空间参考时，交给 `shot-designer` 用 Location Map 与文字 Spatial Blocking 表达；
- 不假设最终视频模型看见了没有实际提交的资产。

## 判断顺序

1. 先列已有资产及其真实职责。
2. 检查本镜真正会被看清的身份、场景、道具和特殊视觉事实。
3. 若地点是独特世界场景／剧情关键场景，先检查 Scene Plate 是否存在且结构职责足够；不要把这一检查留到成片失败后。
4. 检查现有资产与文字是否已经足够。
5. 若不够，选择能直接解决主风险的最小资产类型。
6. 若需要人物与场景的组合站位，分类为故事板／镜头关键帧／previs，不把它伪装成“场景资产”。
7. 形成交接单；实际制作转给 `$jin-gpt-image-director`。

## 实际资产交回后的验收

仅在本轮确实生成或编辑了资产时执行；资产需求单、生图 Prompt 和界面缩略预览都不等于已验收的参考文件。按每张图先前的职责检查实际文件，给出“可用于视频／需修正”结论：

- 角色图看身份、服装和本镜可见的高辨识度结构；
- 无人 Scene Plate 看空间结构、地标、光源与方向，不能混入角色；
- 人物入场关键帧看首个可见状态、人物数量、站位比例、接地受光，以及发型、饰品等可数结构是否与身份资产一致。关键帧只在确有首帧或组合构图需求时制作，不把它变成固定第四张图。

有可见错误时，指出具体文件与需要修正的事实，交回 $jin-gpt-image-director；不要用视频 Prompt 压制错误图。只改变当前失败资产，其余已经验收的素材不机械重做。用户仅要资产计划时，停在交接单，不虚报资产就绪。

## 输出

若无需新增：

```text
【已有】
- 素材：负责什么

【结论】
当前资产已足够；动作、站位或表演继续由视频 Prompt 完成。
```

若存在真实缺口：

```text
【已有】
- 素材：只负责什么

【必须补充】
- 资产类型：
- 只锁：
- 文字不足原因：
- 没有它会失败：
- 使用镜头／平台：

【当前不需要】
- 不生成什么：原因

【交接 Image EXP】
读取 $jin-gpt-image-director。
只交付上述获批资产；由资产 Skill 决定生成、编辑、故事板或 Astra／白膜的具体制作方法。
```

素材判断必须服务当前镜头，不追求资产数量最大化。
