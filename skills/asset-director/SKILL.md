# Asset Director

只判断“这一镜真正需要什么素材，以及每份素材负责什么”。不要把所有角色都机械要求三视图或四视图。

如果已经判断出本镜需要 **16:9 分镜、Blender 白膜 / previs、角色 blocking、动作演员 / Mocap 学习资产或其他复杂可视化载体**，本 Skill 不继续承担制作说明；转交：

`../astra-video-asset-prep/SKILL.md`

由它生成可直接交给 Astra 的专业资产任务书。

## 最小资产门槛（硬规则）

本 Skill 的默认结论是：**现有身份资产 + 清楚的视频 Prompt 已经足够**。额外资产必须证明必要性，不以“多准备一点更稳”为理由。

以下内容默认留在视频 Prompt，不列为资产缺口：

- 普通走、跑、坐、拿、递、抱、指向、敲门、开门、回头、点头及简单接触；
- 眼神、表情、呼吸、停顿、反应先后与完整动作时间线；
- 普通房间、门、床、桌椅等可由模型自然补全的生活空间；
- 普通枕头、杯子、食物等没有独特设计要求的生活道具；
- POV 转头、摄影机点头、轻微手持晃动和简单运镜；
- 为短视频写出的多个动作阶段。动作阶段是时间控制，不是多张静态资产任务。

新增资产前逐项检查：

1. **锁什么：**是否存在一个明确、可见且必须保持的独特设计、关键状态或空间关系？
2. **为什么文字不够：**现有参考与正向 Prompt 为什么不能承担？
3. **失败证据：**是否已有相关生成失败，或动作／空间复杂到存在清楚的高风险点？
4. **是否可用：**目标视频平台能否实际接收或利用该资产？

任一项无法回答，判定为“当前无需补充”，停止扩张资产清单。用户已经明确“只准备这些资产”时，尊重范围，不追加建议性库存。

如果当前平台**无法直接使用白膜 / previs 视频或对应三维预演资产**，不要因此卡住生产流程。改由 `../shot-designer/SKILL.md` 启用文字版 spatial blocking，把第一帧、人物位置、身体朝向、视线、移动路径、摄影机一侧与地标关系写清楚。

如果需要实际生成 / 编辑一张角色、场景、姿态、局部、道具或关键帧资产，转交：

`../image-asset-generator/SKILL.md`

## 判断顺序

1. 先看场景图已经提供什么：空间、人物初始存在、位置、姿态、构图关系、光线或关键物件。
2. 再看本镜真正可见的角度与身份信息。
3. 只有场景图无法稳定承担的信息，才补角色或局部资产。
4. 精确动接优先使用上一镜结尾帧；复杂多镜调度才强制考虑故事板。
5. 如果真正缺的是“空间 / 构图 / 大姿势 / 动作过程的可视化骨架”，不要继续堆角色身份图，改判断是否需要 Astra 资产准备。
6. 如果理论上适合白膜，但目标平台根本无法读取这种资产，立即切换为文字 blocking，不把不可用资产当作必须前置条件。

## 角色资产原则

- 场景图中已经出现的人物，可以先由场景图承载其初始存在、位置和大致姿态。
- 场景图不自动等于精确身份锚点。
- 镜头主要看背影／侧背影坐姿时，可以只提供对应的坐姿轮廓资产，锁定兜帽、服装、年轻男性比例、身体轮廓等本镜真正可见信息。
- 后续才露出正脸时，再补正脸、头部或对应角度资产。
- 后续才入画的新角色，如果场景图没有身份锚点，应补单独角色图。
- 不要为了“完整”而要求本镜根本看不到的多视图。
- 平台 / 参考系统已经能提供身份时，不要靠长篇角色描述与参考图互相竞争。

## 复杂动作 / 空间资产判断

当镜头难点来自以下内容时，考虑转交 `astra-video-asset-prep`：

- 人物位置、朝向或前后关系容易漂移；
- 需要锁定景别、相机位置、人物占比；
- 多角色 / 多层空间 blocking 复杂；
- 需要明显大姿势、重心变化或高难度身体动作；
- 动作更适合通过真人演员、动作捕捉或代理动画学习；
- 正式视频生成成本高，希望先验证空间、机位和动作是否成立。

这种情况下可以按问题选择：

- 16:9 线稿分镜：锁这一镜看什么；
- Blender 白膜 / previs：锁空间、机位、角色位置和大姿势；
- 动作演员 / Mocap / 动作参考：锁身体具体怎么动。

### 平台不支持白膜时

如果白膜无法作为最终视频生成输入：

- 可以继续把白膜当导演 / 分镜设计辅助；
- 但不要假设视频模型“看到了白膜”；
- 真正提交给视频模型的 Prompt 必须用 `shot-designer` 把关键 blocking 重新文字化；
- 如果平台支持静态图但不支持视频，可优先输出白膜关键帧 / 线稿分镜图作为静态参考；
- 如果连静态空间参考也无法使用，则完全依赖文字 Location Map + First Frame + Spatial Blocking。

## 技能特效资产判断

当镜头包含独特技能、施法、能量形态或特殊视觉元素时，先检查文字是否已经能够清楚说明其**可见形态**。

如果可以稳定描述，例如“双手之间汇聚一个持续增亮的蓝色能量球”，优先使用清楚文字，不机械增加资产。

如果技能具有强辨识度，而文字很难准确表达它的形状、结构、材质、颜色关系、运动轨迹或与角色／武器的连接方式，则把**技能特效本体**视为一种可选参考资产，并提醒使用者考虑先生成对应的技能特效参考图，再用于后续视频生成。

例如可能需要资产的情况：

- 独特符文阵或复杂几何能量结构；
- 特定世界观专属火焰、烟雾、晶体或粒子形态；
- 与武器结合方式非常具体的技能；
- 仅用“魔法、能量、贤者技能”等抽象词容易被模型生成成泛用特效的情况。

不要把“有技能镜头”自动等同于“必须补技能资产”。先判断文字是否足够，再决定是否建议补充。

## 资产职责必须单一清楚

每份参考说明：

- 只负责锁定什么；
- 不继承什么；
- 白底、文字、旧构图、错误人物位置是否进入画面；
- 若是多视图，是否为同一对象。

如果用户明确说明真实资产与界面预览不一致，以用户说明为准，不从错配预览反推生成输入。

## 故事板与动接

- 单一跟随动作或简单切镜不强制故事板。
- 多角色、多层空间、复杂起落幅或连续调度时建议故事板。
- 精确动接最好提供上一镜结尾帧；没有时至少记录连接物、屏幕方向、速度、位置与摄影机状态。

## 输出

只有存在真实资产缺口时才按以下四区输出；如果现有资产已经足够，只输出【已有】与“当前无需补充”，不要为了填满格式制造【建议补充】：

```text
【已有】
- 素材：负责什么

【必须补充】
- 素材：为什么必须

【建议补充】
- 素材：会提升什么稳定性

【当前不需要】
- 素材：为什么本镜不需要
```

若需要 Astra 制作复杂资产，在上述判断后增加：

```text
【转交 Astra 资产准备】
- 需要的载体：...
- 原因：...
- 当前平台能否直接使用该资产：...
- 下一步：读取 ../astra-video-asset-prep/SKILL.md 生成完整执行提示词。
```

若白膜 / previs 无法被最终平台使用，则增加：

```text
【文字 Blocking 回退】
- 必须文字化的空间信息：...
- 下一步：读取 ../shot-designer/SKILL.md。
```

素材判断必须服务本镜，不追求资产数量最大化。
