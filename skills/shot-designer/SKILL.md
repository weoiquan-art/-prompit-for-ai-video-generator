# Shot Designer

只负责“这一镜怎样被摄影机看见并完整发生”。

当前方法吸收了 `../practical-case-skills/cinedance-v4/SKILL.md` 中已经用于 Seedance / Higgsfield 实操的空间 blocking、第一帧与镜头控制经验，但不照搬其全部平台特定参数。

## 核心要求

每镜只完成一个主要变化。先写本镜唯一任务，再搭建空间、第一帧、摄影机与动作。

至少确定：

- 本镜唯一任务；
- 第一可见帧；
- 景别；
- 水平角度；
- 纵向角度；
- 摄影机位置、距离与一侧；
- 摄影机是否移动、怎样移动、为什么移动；
- 前景／中景／后景；
- 重要人物与地标的 blocking；
- 身体朝向与视线方向；
- 起幅；
- 过程；
- 落幅；
- 焦点变化与镜头内不变量（按需）；
- 剪辑出口；
- 本镜不得提前发生的后续关键动作（按需）。

## 两种工作模式

### A. 有可用分镜 / 白膜 / previs

如果当前视频模型能够直接使用有效分镜、关键帧或三维预演资产，并且这些资产已经清楚锁定：

- 人物位置；
- 相机角度；
- 大姿势；
- 前后层级；
- 运动方向；

本 Skill 不用在最终视频 Prompt 里逐句重复整套几何信息，只做必要确认，并把文字预算留给动作时间、表演、物理、灯光和声音。

### B. 无法使用白膜 / previs

如果当前平台无法导入白膜视频、预演结果或对应空间资产，**不要停在“缺资产”这一步**。改用文字版 spatial blocking，把本来由白膜承担的信息直接写清楚。

此时优先完成：

1. Location Map；
2. 第一帧占位；
3. 角色位置；
4. 身体朝向；
5. 视线；
6. 移动方向；
7. 摄影机位置与一侧；
8. 与地标 / 道具的接触或距离关系。

## Location Map：先把场景变成可执行空间

空间复杂时，不要先写“电影感构图”。先记录：

- 摄影机在哪里；
- 摄影机朝哪个方向；
- 前景是什么；
- 中景是什么；
- 后景是什么；
- 主要地标在哪里；
- 角色分别在哪里；
- 角色会往哪里移动；
- 主要光源从哪里来；
- 画面深度怎样组织。

场景参考图可以锁地理、材质、氛围与地标，但**不自动继承它原本的机位和构图**，除非用户明确要求。

## 第一帧占位

第一帧是独立控制对象。

如果人物应该从一开始就存在，直接写清：

- 第一可见帧已经包含必要人物；
- 人物已经处于正确位置；
- 空间关系第一帧即可读懂；
- 不先插入无人物空镜；
- 不让必要人物延迟出现。

只有剧情明确需要空镜时才允许空开场。

## Spatial Blocking

对白膜不可用、多人关系复杂或左右容易漂移的镜头，重要人物至少说明：

- screen-left / screen-right；
- foreground / midground / background；
- 与地标或另一角色的物理关系；
- 身体朝向；
- 视线方向；
- 移动方向。

当距离本身决定画面时，不只写“附近 / 旁边”。优先写成可执行关系，例如：

- 距离装置约 1 米；
- 背靠墙；
- 手已经在门把上；
- 站在标志正下方；
- 两人前后相隔一个明确层级。

## 身体朝向与视线分开

身体和眼睛不是同一个控制量。

例如：

```text
身体仍朝走廊前方；
眼睛先落到画面右侧装置；
随后头部才轻微转过去。
```

特别适用于：回头、偷看、警觉、对峙、战斗预判、边走边观察。

## 镜头 / Optics：优先写可见结果

焦段数字、品牌或光圈可以作为辅助，但不要把 metadata 当成唯一控制。

优先说明：

- 摄影机离主体多远；
- 画面是自然透视、广角空间展开还是长焦压缩；
- 人物在画面中占多少；
- 环境是否需要保持可读；
- 背景是否被压缩并柔化；
- 前景是否因摄影机靠近而放大；
- 是否需要主体明显从背景分离；
- 景深与焦点结果。

不要机械要求固定 FOV 数字；只在当前模型和任务确实需要时使用。

## 摄影机写成真实操机行为

优先写：

- 摄影机高度；
- 与主体实际距离；
- 摄影机位于主体哪一侧；
- 仰拍 / 平视 / 俯拍；
- 主体占画面多大；
- 主体在 screen-left / right / center 的位置；
- 摄影机从 X 移到 Y；
- 焦点怎样变化。

如果需要手持，不写“random shake”。更适合写人体操机造成的轻微呼吸、重量 settling、肩扛感和自然修正。

## 设计原则

1. 起幅、过程、落幅必须组成真实状态变化，不要只是三段同义描述。
2. 景别回答“看多少”，水平角度回答“从哪一侧看”，纵向角度回答“从多高/多低看”。
3. 空间规则先于摄影风格；关键站位不要埋进“电影感”形容词。
4. 运镜必须跟随动作、视线、遮挡或空间揭示，不要拿运镜替代角色动作。
5. 摄影机移动时，按需要写清空间揭示顺序，例如：前景树叶和山雾 → 亭檐灯笼 → 亭柱栏杆 → 坐姿人物与瀑布。
6. 前景负责距离、遮挡和进入接口；中景承载当前中心事件；后景稳定空间方向与环境反馈。
7. 一个连续镜头若有重要不变量，明确写出，例如摄影机横移时高度始终保持在人物胸口。
8. 落幅必须可以被下一镜继承，不能写成不存在的“抽象结束”。
9. 时长不足时减镜，不压缩所有动作。
10. Prompt 只在真正需要控制的空间位置写细；已经由参考资产稳定提供的信息不要重复堆叠。

## 技能 / 特效镜头：先定义可见载体

当镜头任务涉及施法、聚力、技能释放、能量修炼或其他特殊能力时，不要只写抽象技能名，例如“施法”“聚力”“贤者能量”“释放力量”。

优先把技能翻译成镜头中能直接看见的**特殊元素或视觉载体**，例如：

- 双手之间持续汇聚的蓝色能量球；
- 围绕手腕旋转的金色符文环；
- 从掌心向外扩散的冰晶碎片旋涡；
- 沿武器表面爬行的红色电弧；
- 被双手压缩并逐渐增亮的黑色烟雾核心。

至少说清本镜需要时可见的：

1. 技能的主要形态；
2. 颜色或材质表现；
3. 它出现在哪里、与角色身体／武器怎样关联；
4. 它如何从弱到强或从起始状态发展到结果状态；
5. 达到顶峰后怎样结束、爆发或成为下一镜接口。

目标不是把所有特效写得复杂，而是避免让模型只根据抽象技能名称自行生成泛用魔法效果。

若某种技能视觉形态很独特、文字无法稳定说明，不在本 Skill 中强行堆形容词；交给 `asset-director` 判断是否需要补专门的技能特效参考资产。

## 输出骨架

```text
【本镜唯一任务】

【第一可见帧】

【Location Map / 空间关系】（空间复杂或无白膜时）
摄影机：
前景：
中景：
后景：
地标 / 道具：
人物位置与移动路径：

【景别】
【水平角度】
【纵向角度】
【摄影机距离 / 一侧 / 运动】
【Optics 可见结果】（按需）

【角色 Blocking】
身体朝向：
视线：
与地标 / 对手距离：
移动方向：

【起幅】
【过程】
【落幅】

【焦点变化 / 镜头内不变量】（按需）
【本镜不得提前发生】（按需）
```

不要在本 Skill 中展开角色微表演、声音或通用负面词库。
